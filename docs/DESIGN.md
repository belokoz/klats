# Клац — дизайн

Принят 17 сентября 2026. Макеты лежат на холсте: <https://claude.ai/artifact/J5bMwTKmmaSBtUaQrJD1zd>. Продуктовые решения описаны в [CONCEPT.md](CONCEPT.md).

## Экраны

Номера совпадают с номерами на холсте.

1. **Меню в строке меню.** «Сменить раскладку выделенного» `⌥⌘`, «Сменить регистр выделенного» `⌥⌘Z`, «Приостановить», «Настройки…» `⌘,`, «О программе Клац», «Завершить Клац» `⌘Q`. Пункты действий показывают хоткеи и работают мышью.
2. **Настройки.** Одно окно без вкладок, четыре группы: горячие клавиши (два поля записи), раскладка (пара раскладок, переключатель «Переключать раскладку после конвертации»), регистр (инвертировать или все строчные, с примером), общие (автозапуск, состояние Универсального доступа). Внизу версия, лицензия и ссылка на репозиторий.
3. **Первый запуск, ждём разрешения.** Три шага в одном окне. Первый активен: зачем нужно разрешение, путь в системных настройках, кнопка «Открыть системные настройки», индикатор «Ждём разрешения…».
4. **Первый запуск, проба.** Первый шаг свёрнут в «Разрешение выдано». Второй: поле с «ghbdtn vbh», которое надо выделить и сконвертировать. Третий: галочка автозапуска (стоит по умолчанию) и кнопка «Готово».
5. **Поле хоткея, состояния.** Обычное, запись, запись с зажатыми клавишами, занято системой, конфликт с другим действием, не задано. Сочетание из одних модификаторов записывается, если отпустить клавиши без буквы.
6. **Меню без разрешения.** Заголовок «Клацу нужно разрешение», пункт «Выдать разрешение…», действия выключены. На иконке точка.
7. **Меню на паузе.** Действия выключены, пункт «Возобновить». Иконка приглушена.
8–9. Меню и настройки в светлом оформлении. Приложение следует оформлению системы.
10. **Иконка.** Клавиша с латинской K и красной русской Л: так выглядит настоящая клавиша K на русской клавиатуре, вместе читается «Кл». В строке меню упрощённый контур клавиши с K, шаблонное изображение.
11. **Устройство.** См. ниже.

Тексты интерфейса на «вы». Системные контролы стандартные, акцентный цвет системный. Фирменный красный живёт только в иконке.

## Устройство

Два модуля в одном Swift-пакете.

**KlatsCore** — чистая логика без системных вызовов, покрыта тестами.

| Тип | Что делает |
|---|---|
| `KeyStroke` | Клавиша плюс состояние Shift |
| `LayoutTable` | Раскладка как две таблицы: клавиша → символ и символ → клавиша |
| `LayoutConverter` | Определяет направление по тексту и перепечатывает его в другой раскладке |
| `CaseConverter` | Инвертирует регистр или делает всё строчным |
| `ChordDetector` | Автомат для хоткея из одних модификаторов |

**Klats** — приложение, всё, что трогает систему.

| Тип | Что делает |
|---|---|
| `HotkeyTap` | Один перехватчик `CGEventTap` для обоих хоткеев |
| `SelectionReplacer` | Конвейер одного нажатия |
| `PasteboardSnapshot` | Снимок буфера обмена и его возврат |
| `SyntheticKeys` | Синтетические `⌘C` и `⌘V`, помеченные, чтобы свой же перехватчик их пропускал |
| `InputSources` | Список раскладок, текущая, переключение, построение `LayoutTable` через `UCKeyTranslate` |
| `Permissions` | Универсальный доступ, защищённый ввод |
| `Settings` | Настройки в `UserDefaults` |
| `StatusItemController` | Иконка и меню |
| `Log` | Журнал в `~/Library/Logs/Klats/klats.log`. Текст не пишется никогда: только длины, время, исход и идентификатор приложения |

### Почему один перехватчик

`⌥⌘` система зарегистрировать не может, за модификаторами приходится следить самим. Если рядом зарегистрировать `⌥⌘Z` через Carbon, система проглотит это нажатие раньше, чем его увидит детектор `⌥⌘`, и после `⌥⌘Z` сработала бы ещё и смена раскладки. В одном перехватчике все события приходят по порядку.

### Правила для `⌥⌘`

Срабатывает при отпускании, если: к сочетанию пришли нажатием, а не отпусканием лишней клавиши; пока оно было зажато, не было ни клавиш, ни кликов, ни прокрутки; не добавлялись другие модификаторы; удержание короче секунды; кнопки мыши не зажаты. После срабатывания нужно отпустить всё, прежде чем сочетание сработает снова. Поэтому `⌥⌘Esc`, `⌥⌘D` и перетаскивание с `⌥⌘` работают как раньше.

### Одно нажатие по шагам

1. Хоткей пойман.
2. Нет разрешения — системный запрос, выходим.
3. Ждём до 0,6 с, пока пользователь отпустит модификаторы: иначе `⌘C` может дойти до приложения как `⌥⌘C`.
4. Снимок буфера обмена.
5. `⌘C`. Ждём до 0,5 с изменения буфера. Не изменился — ничего не выделено, выходим, буфер не тронут.
6. В буфере не текст — возвращаем снимок, выходим.
7. Преобразование. Таблицы раскладок строятся тут же (0,2 мс), кэша нет. При равенстве голосов исходной считается текущая раскладка.
8. Результат не отличается — возвращаем снимок, выходим.
9. Результат в буфер с пометкой `org.nspasteboard.TransientType`, затем `⌘V`.
10. Переключаем системную раскладку на язык результата, если включено.
11. Через 0,3 с возвращаем снимок, если буфер за это время не поменял кто-то другой.

Клавиша для `⌘C` и `⌘V` ищется в текущей раскладке, чтобы работало и в Dvorak.

### Отложено

Быстрая проверка «есть ли выделение» через Accessibility API, шаг 3 на макете 11. Без неё случайное `⌥⌘` при пустом выделении даёт системный «бип» в нативных приложениях, и это честная обратная связь. С ней есть два риска: запрос может включить у Chrome тяжёлый режим доступности, и приложение может ответить «пусто», когда выделение есть. Вернёмся, если «бип» будет мешать в обкатке.

Известная особенность: VS Code и похожие редакторы при пустом выделении копируют всю строку, поэтому случайное `⌥⌘` там вставит сконвертированную копию строки.

## Сборка и тесты

Xcode не нужен, хватает Command Line Tools.

```bash
./scripts/test.sh                      # тесты ядра
./scripts/build-app.sh                 # build/Клац.app, Apple Silicon + Intel
ARCHS=arm64 ./scripts/build-app.sh     # только этот Mac, быстрее
./scripts/install.sh                   # собрать, заменить копию в /Applications и запустить
```

Журнал: `~/Library/Logs/Klats/klats.log`, открывается из меню с зажатой ⌥. Текста в нём нет: только приложение, время, длины и исход.

## Подпись

Аккаунта Apple Developer нет, поэтому скачанную копию macOS откроет только через «Открыть всё равно». Но разрешение «Универсальный доступ» система запоминает по подписи, и с подписью ad-hoc оно слетало бы после каждого обновления. Поэтому приложение подписывается постоянным самоподписанным сертификатом «Klats Signing»: `scripts/make-signing-cert.sh` создаёт его в связке ключей один раз (на 10 лет), `scripts/build-app.sh` подхватывает автоматически, а без него подписывает ad-hoc. Тот же приём использовал AltTab до получения Developer ID.

Первое использование ключа macOS подтверждает диалогом связки ключей: «Всегда разрешать» убирает его насовсем. Сертификат живёт только в связке ключей, в репозитории его нет.
