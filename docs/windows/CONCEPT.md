# Клац для Windows — концепция

Принята 5 октября 2026. Продукт тот же, что на macOS ([CONCEPT.md](../CONCEPT.md)). Здесь только то, что на Windows устроено иначе. Факты проверены пробными программами на ПК автора (Windows 10 22H2, раскладки «Русская» и «США», UAC выключен), исходниками и документацией и перепроверены отдельно. То, что можно проверить только руками в настоящих приложениях, на Windows 11 или с включённым UAC, вынесено в прототип.

## Что это

Клац живёт в области уведомлений Windows и умеет одну вещь: по `Win+Alt` переводит выделенный текст в другую раскладку. «ghbdtn» становится «привет», «руддщ» становится «hello». Той же механикой `Win+Alt+Z` меняет регистр выделенного. `Win` и `Alt` стоят слева от пробела на тех же местах, что `⌥` и `⌘` на маке, поэтому руки делают то же движение.

Отдельная кодовая база на C++ и Win32 API в папке `windows/` того же репозитория, что и мак-версия: один проект, две сборки, каждый скачивает свою. Ядро переносит KlatsCore с теми же тестами. На раскладках «Русская» и «США» конвертация совпадает с мак-версией символ в символ. Как поступать с мёртвыми клавишами (US-International, немецкая, «Русская — мнемоническая»), решим после проверки на маке и на Windows с этими раскладками.

В России Windows стоит примерно на 91% компьютеров, macOS на 5%. Из них Windows 10 — 54%, Windows 11 — 43%.

## Принципы

Те же шесть, что на маке.

1. **Одна функция, сделанная хорошо.** Смена раскладки выделенного текста, регистр бонусом. История буфера обмена на Windows не нужна: есть встроенная `Win+V`.
2. **Ничего лишнего.** Нет автопереключения, автозамены, словарей, статистики, звуков, фоновых обновлений.
3. **Лёгкая.** C++ и Win32, без .NET, Electron и сторонних библиотек. Один `Klats.exe` в несколько сотен килобайт, всё остальное — части Windows. Прототип с потоком перехватчика, значком, окном настроек и запросом к GitHub занимает в Диспетчере задач около 3 МБ и не тратит процессор в покое. Это замер на Windows 10, полную сборку перемерим, в том числе на Windows 11.
4. **Текст не уходит наружу.** Единственный сетевой запрос: раз при запуске спросить у GitHub, вышла ли новая версия, выключается в настройках. Текст не сохраняется и не логируется. Сконвертированный текст помечен так, чтобы его не запоминали журнал `Win+V`, облачный буфер и менеджеры буфера. Копию выделенного делает само приложение, и пометить её нельзя. Клац заменяет её за доли секунды, но если журнал, Ditto или облачная синхронизация успеют её прочитать, выделенный текст останется там.
5. **Ставится за минуту.** Установщик без прав администратора. Окно SmartScreen «Подробнее → Выполнить в любом случае» — при установке и после каждого обновления. Разрешений Windows не спрашивает.
6. **Открытая.** Код на GitHub под MIT.

Из решений мак-версии здесь действуют Р2 (имя Klats), Р5 (переключать раскладку после конвертации), Р6 (регистр инвертировать), Р7 (MIT) и Р8 (обновления).

## Сценарии

- **Раскладка.** Печатаешь, видишь «ghbdtn», выделяешь, нажимаешь и отпускаешь `Win+Alt`. Текст стал «привет», раскладка Windows переключилась на русскую.
- **Регистр.** «пРИВЕТ» → выделил → `Win+Alt+Z` → «Привет» (режим «инвертировать») или «привет» («все строчные»).
- **Первый запуск.** Установщик, окно SmartScreen, затем одно окно Клаца: проба на тестовом поле, где искать значок (новые значки Windows прячет за стрелкой ^ у часов) и галочка автозапуска. Сочетания работают сразу.

## Как это работает

**Сочетания.** Один низкоуровневый перехватчик клавиатуры `WH_KEYBOARD_LL` на отдельном потоке, как один `CGEventTap` на маке: все события приходят по порядку. Если перехватчик отвечает дольше секунды, Windows пропускает событие мимо него, а после серии таких задержек может снять совсем. Поэтому в его потоке живёт только детектор, вся работа идёт в другом потоке, а после сна и разблокировки перехватчик ставится заново. Правила для `Win+Alt` те же, что для `⌥⌘`: срабатывает при отпускании, если между нажатием и отпусканием не было клавиш, кликов и прокрутки, не добавлялись модификаторы и удержание короче секунды. Клики видит мышиный перехватчик, который живёт только пока зажат модификатор: постоянный стоил бы процессора на каждом движении мыши. Одиночное отпускание `Win` открывает меню «Пуск», одиночное `Alt` — меню программы. Поэтому в момент срабатывания Клац вставляет пустое нажатие неназначенной клавиши (`vkE8`, приём AutoHotkey). Что меню программы так не открывается, показала проба. Что не открывается «Пуск», проверим в прототипе.

**Замена текста.** Конвейер тот же, что на маке, с отличиями.

- Копирование через `Ctrl+Insert`, вставка через `Shift+Insert`. В терминале `Ctrl+C` без выделения прерывает запущенную команду, `Ctrl+Insert` — нет. В VS Code с расширением Vim `Ctrl+C` и `Ctrl+V` — команды Vim, а `Ctrl+Insert` и `Shift+Insert` копируют и вставляют. По исходникам эти сочетания понимают Chrome, Edge, Firefox, Telegram, VS Code, LibreOffice, Notepad++, JetBrains и стандартные поля Windows. Word, Excel и Outlook проверим в прототипе. Когда работает программа чтения с экрана NVDA или JAWS, Клац копирует через `Ctrl+C`: NVDA забирает `Insert` себе. Встроенный «Экранный диктор» тоже держит `Insert`, проверим в прототипе. Тем, у кого `Insert` отключён переназначением клавиш, поможет переключатель в реестре.
- Сконвертированный текст лежит в буфере с пометками `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory = 0` и `CanUploadToCloudClipboard = 0`, это аналог `org.nspasteboard.TransientType`. На ПК автора проверено, что такой текст не попадает в журнал `Win+V`. Ditto и CopyQ, судя по их исходникам, его не сохраняют.
- Буфер возвращается через 0,3–2 с. Сколько ждать, Клац решает по тому, как быстро приложение ответило на копирование: Chromium читает буфер не сразу, а под нагрузкой опаздывает любое приложение.
- VS Code и Notepad++ при пустом выделении копируют всю строку. По исходникам такую копию видно по служебной пометке, и тогда Клац ничего не делает. На маке такой проверки пока нет.

**Одно нажатие по шагам.**

1. Сочетание поймано в потоке перехватчика, работа уходит в рабочий поток. Запоминаем окно с фокусом.
2. На переднем плане терминал, удалённый стол, виртуальная машина, полноэкранная игра, окно администратора или зависшее окно — выходим, ничего не трогая.
3. Ждём до 0,6 с, пока пользователь отпустит модификаторы. Не отпустил — выходим.
4. Снимок буфера обмена: все форматы, которые можно сохранить, в исходном порядке. Владелец буфера не отвечает или снимок слишком большой — выходим, буфер не тронут.
5. `Ctrl+Insert`. Ждём до 0,5 с изменения номера буфера. Не изменился — ничего не выделено или это поле пароля, выходим, буфер не тронут.
6. В буфере не текст или копия целой строки из редактора — возвращаем снимок, выходим.
7. Преобразование. Таблицы раскладок строятся тут же. При равенстве голосов исходной считается текущая раскладка окна с фокусом.
8. Результат не отличается — возвращаем снимок, выходим.
9. Фокус ушёл в другое окно — возвращаем снимок, выходим. Иначе результат в буфер с пометками, затем `Shift+Insert`.
10. Переключаем раскладку окна с фокусом на язык результата, если включено.
11. Через 0,3–2 с возвращаем снимок, если буфер за это время не поменял кто-то другой. Если Клац в это время завершают или Windows выключается, снимок возвращается сразу.

**Конвертация.** Таблицы «символ ⇄ клавиша» строятся из раскладок Windows через `ToUnicodeEx` по физическим клавишам (скан-кодам), поэтому работают и французская AZERTY, и немецкая QWERTZ. Их проверили по таблицам из файлов раскладок, вживую — нет. Обе таблицы строятся за 0,3–0,5 мс, алгоритм тот же. Составные символы, эмодзи и регистр по правилам Юникода («straße» → «STRASSE») обрабатывает ICU, встроенный в Windows 10 1903+. На настоящих раскладках ПК автора проходят все 26 мак-тестов конвертации.

**Переключение раскладки.** Окну с фокусом уходит `WM_INPUTLANGCHANGEREQUEST`, затем Клац проверяет, что раскладка сменилась. С Windows 8 раскладка общая для всех окон, если не включено «Позволить выбирать метод ввода для каждого окна приложения».

**Где Клац ничего не делает.** Терминалы, удалённые рабочие столы и виртуальные машины (по классу окна и имени процесса), полноэкранные игры. Окна программ, запущенных от имени администратора: Windows не пускает туда нажатия обычной программы. Пока такое окно впереди, меню Клаца пишет об этом первой строкой, как мак-версия пишет о защищённом вводе. Поля паролей сами не отдают текст.

**Из чего сделано.** C++20, Win32 API, MSVC из Build Tools 2022, CMake и Ninja, статическая CRT. Настройки в `HKCU\Software\Klats`, журнал в `%LOCALAPPDATA%\Klats\klats.log`. Текста в журнале нет: только приложение, время, длины и исход. Автозапуск через ключ `Run` в реестре пользователя; если его выключили в Диспетчере задач, Клац показывает это в настройках. Тесты ядра запускаются без IDE, на своём маленьком раннере без зависимостей. Windows 10 (1903 и новее) и Windows 11, 64-бит.

## Релизы в общем репозитории

Мак-версия 0.2.0 проверяет обновления по «последнему» релизу GitHub и предлагает его, если номер в теге новее. Поэтому правила такие.

- «Последней версией» на GitHub всегда остаётся мак-версия. Windows-релизы публикуются с `--latest=false`, и скрипт выпуска после публикации проверяет, что «последней» осталась мак-версия.
- Теги Windows — `windows-vX.Y.Z`, у Windows свой счёт версий с 0.1.0. Мак-версия 0.2.0 такой тег не прочитает и промолчит, даже если ошибкой он станет «последним».
- Установщик в релизе называется `Klats-X.Y.Z-windows-x64.exe`. Латиница, потому что GitHub вырезает кириллицу из имён файлов.
- Windows-версия ищет обновления в ленте релизов `releases.atom`: берёт записи этого репозитория (номер 1375942669 в записи) с тегом `windows-v` и одними цифрами в номере. Лента не расходует лимит API GitHub (60 запросов в час с одного адреса, за VPN он быстро кончается). Пробные сборки помечаются суффиксом в теге (`windows-v0.2.0-beta`) и никому не предлагаются.
- Лента показывает и голые теги, без релиза. Тег `windows-v` создаёт только `gh release create` вместе с релизом, а снимается релиз только с тегом: `gh release delete windows-vX.Y.Z --cleanup-tag`.
- В README и на сайте две кнопки: «Скачать для macOS» ведёт на «последний» релиз, «Скачать для Windows» — на свежий `windows-v` релиз, ссылку обновляет скрипт выпуска.
- В следующем мак-релизе проверка обновлений будет требовать DMG в релизе и не открывать страницу релиза без него.

## Ограничения и риски

- **Нет подписи.** Браузер предупреждает при скачивании, SmartScreen — при первом запуске каждой новой версии: «Система Windows защитила ваш компьютер» → «Подробнее» → «Выполнить в любом случае». Яндекс Браузер, у которого в России треть пользователей, может вовсе не дать скачать неподписанный файл. Проверим на настоящем релизе в Chrome, Яндекс Браузере, Edge и Opera.
- **«Интеллектуальное управление приложениями»** на Windows 11 не даст запустить неподписанный Клац вовсе. Разрешить одно приложение нельзя, можно только выключить эту защиту целиком, а на новых установках Windows 11 она часто включается сама. В S-режиме Windows запускает только программы из Microsoft Store. Поэтому до выпуска пробуем Microsoft Store (W8).
- **Антивирусы.** Перехват клавиатуры, буфер и синтетические нажатия вместе похожи на кейлоггер. Перед каждым релизом сборку проверяем на VirusTotal и под Касперским, ложное срабатывание отправляем на перепроверку в Microsoft и Kaspersky. «Безопасные платежи» Касперского закрывают буфер для непроверенных программ, и там Клац молча ничего не сделает.
- **Окна администратора** (Диспетчер задач, терминал от администратора): Клац там не работает. На ПК автора выключен UAC, и все программы запущены с правами администратора, поэтому это проверяется только на другом компьютере.
- **Соседи-перехватчики.** Общее с Punto Switcher сочетание конвертирует текст дважды, и он вернётся к исходному. Перехватчик Клаца видит клавиши раньше сочетаний, зарегистрированных другими программами, и молча забирает совпавшие себе. Программа, которая ловит `Ctrl+Alt+клавиша` своим перехватчиком и прячет клавишу (так может делать Диктуй с `Ctrl+Alt+Space`), вызвала бы ложное срабатывание сочетания `Ctrl+Alt`. С `Win+Alt` такого пересечения нет.
- **Чужие читатели буфера.** Программы, которые не уважают пометки (на ПК автора так делает VPN-клиент Happ), видят и выделенный, и сконвертированный текст. Копию выделенного, которую делает само приложение, журнал `Win+V` обычно не успевает запомнить, но гарантии нет: время Microsoft не документирует, а каждая попавшая туда копия вытесняет самую старую из 25 записей.
- **Буфер возвращается не всегда точь-в-точь.** Файлы из архивов и вложения Outlook пропадут, у Excel и Проводника сбросится отметка копии. Если в буфере огромная копия из Office, Клац не конвертирует.
- **Excel.** Выделенные ячейки копируются целиком, и вставка заменит формулы текстом.
- **Открытые пароли.** Пароль, показанный кнопкой с глазом в браузере, копируется как обычный текст. Защищённого ввода, как на маке, у Windows нет.
- **Клац внутри удалённого рабочего стола.** Если к этому ПК подключаются по RDP, выделенный и сконвертированный текст уходят через общий буфер на компьютер клиента.
- **Терминалы** пропускаются. Встроенный терминал VS Code по исходникам отличается от редактора тем, что не ставит в копию служебную пометку, и многострочный результат туда Клац вставлять не будет; проверим в прототипе. Терминал в других программах (JetBrains) распознать нельзя, вставка многострочного результата туда может выполнить команды. На маке так же.
- **Значок.** Новые значки Windows прячет за стрелкой у часов, и программа это изменить не может. Окно первого запуска показывает, как вытащить значок на панель задач.
- Вставляется простой текст. Методы ввода (японский, китайский, корейский) в пары не входят. Как на маке.

5. Публикация — README с двумя кнопками, релиз, сайт. Мак-часть переезжает в папку `macos/` на маке, где её сборку можно проверить. Microsoft Store, если получится регистрация.

## Принятые решения

| № | Вопрос | Решение |
|---|---|---|
| W1 | На чём писать | C++ и Win32: один exe без зависимостей, никакой сборки мусора рядом с перехватчиком. Так сделан ZoomIt от Microsoft |
| W2 | Где живут код и релизы | Один репозиторий с мак-версией: код в папке `windows/`, релизы с тегами `windows-vX.Y.Z` по правилам выше |
| W3 | Сочетания по умолчанию | `Win+Alt` и `Win+Alt+Z`: те же клавиши, что `⌥⌘` на маке |
| W4 | Чем копировать и вставлять | `Ctrl+Insert` и `Shift+Insert`, если пройдут проверку в Word, Excel и Outlook; с программой чтения с экрана — `Ctrl+C` и `Ctrl+V` |
| W5 | Какие Windows | 10 (1903 и новее) и 11, 64-бит. ARM — когда будет на чём проверить |
| W6 | Установка | Установщик на одного пользователя без прав администратора (Inno Setup): ярлык в «Пуске», удаление через «Параметры» |
| W7 | Обновления | Как на маке (Р8): раз при запуске проверить ленту релизов, скачивание в браузере, установка поверх старой версии |
| W8 | Подпись | Без подписи, как Р1. До выпуска пробуем бесплатную регистрацию разработчика в Microsoft Store; SignPath — когда у проекта будут пользователи |
| W9 | Тёмная тема | Значок и меню следуют теме панели задач с 0.1. Окна — по теме приложений, если на Windows 11 это пройдёт проверку к 0.1, иначе следующей версией |
| W10 | Слова в меню | По-виндовски: «Параметры…», «О программе», «Выход», галочка у «Приостановить» |
