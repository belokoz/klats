# Клац для Windows — дизайн

Принят 5 октября 2026. Продуктовые решения описаны в [CONCEPT.md](CONCEPT.md), мак-версия — в [../DESIGN.md](../DESIGN.md). Здесь только то, что на Windows устроено иначе.

## Окна

Номера совпадают с экранами мак-версии.

1. **Меню значка.** «Сменить раскладку выделенного» `Win+Alt`, «Сменить регистр выделенного» `Win+Alt+Z`, «Приостановить» (галочка), «Параметры…» (жирный, по умолчанию), «О программе», «Выход». Сочетания стоят справа, через табуляцию. Открывается сразу по левому и правому щелчку и с клавиатуры; у двойного щелчка своего действия нет. «Открыть журнал» появляется, если открыть меню мышью с зажатым Shift.
2. **Параметры.** Одно окно без вкладок, четыре группы: сочетания клавиш (два поля записи), раскладка (пара раскладок, «Переключать раскладку после конвертации»), регистр («Инвертировать» или «Все строчные», с примером), общие («Запускать при входе в Windows», «Проверять обновления при запуске»). Внизу версия, лицензия, ссылка на репозиторий и «Диктуй: голос в текст». Изменения применяются сразу, кнопок «ОК» и «Отмена» нет.
3–4. **Первый запуск.** Одно окно, шагов с разрешением нет. «Попробуйте»: поле с выделенным «ghbdtn vbh» и подсказка про `Win+Alt`. «Где живёт Клац»: картинка области уведомлений и путь, как вытащить значок из-за стрелки ^, кнопка «Открыть параметры панели задач». Галочка «Запускать Клац при входе в Windows» (стоит) и «Готово». Строка: в окнах программ, запущенных от имени администратора, Клац не работает.
5. **Поле записи сочетания.** Те же состояния, что на маке: обычное, запись, запись с зажатыми клавишами, занято системой, занято другим действием, не задано. Клавиши подписаны текстом: `Win`, `Ctrl`, `Alt`, `Shift` в этом порядке, буквы и `Пробел`.
6. **Меню, когда впереди окно администратора.** Первой строкой «Окно администратора: здесь Клац не работает». Если перехватчик не встал — «Клац не может следить за клавиатурой».
7. **Меню на паузе.** Действия убраны, у «Приостановить» галочка, значок приглушён.
8–9. **Тёмная и светлая тема.** Значок и меню следуют теме панели задач, окна — теме приложений (если тёмные окна пройдут проверку к 0.1).
10. **Значок.** Клавиша с K и Л, как на маке, в exe и ярлыке. В области уведомлений — контур клавиши с K: белый на тёмной панели задач, тёмный на светлой, нарисован под размер 16, 20 и 24 пикселя.
11. **Вышел Клац …** Окно с кнопками «Скачать» и «Не сейчас»; Esc — «Не сейчас».

Тексты интерфейса на «вы». Контролы стандартные Win32, шрифт — системный шрифт сообщений (Segoe UI).

## Устройство

Код в папке `windows/`. Два слоя, как на маке.

**core** (`windows/src/core`) — чистая логика без вызовов Windows, покрыта тестами. Юникод даёт ICU из Windows (`icu.dll`).

| Тип | Что делает |
|---|---|
| `Modifiers`, `ChordDetector` | Четыре модификатора (Shift, Ctrl, Alt, Win) и автомат сочетания из одних модификаторов, перенос с мака |
| `Hotkey` | Сочетание: клавиша (VK) плюс модификаторы, хранится в реестре одним числом |
| `KeyStroke`, `LayoutTable` | Раскладка как две таблицы; клавиша — это скан-код плюс Shift |
| `LayoutConverter` | Направление по тексту и перепечатка в другой раскладке |
| `CaseConverter` | Инвертировать или всё строчными, по правилам Swift |
| `Unicode` | Графемы, NFC и регистр через ICU |
| `AppVersion`, `ReleaseFeed` | Номер версии и свежий `windows-v` релиз из ленты `releases.atom` |

**app** (`windows/src/app`) — всё, что трогает систему.

| Тип | Что делает |
|---|---|
| `HookThread` | Поток с `WH_KEYBOARD_LL` и, на время сочетания, `WH_MOUSE_LL`: детектор, маска `vkE8`, запись сочетания для поля настроек |
| `Pipeline` | Конвейер одного нажатия на своём потоке, шаги по таймерам |
| `ClipboardSnapshot` | Снимок буфера обмена и его возврат |
| `SyntheticKeys` | `Ctrl+Insert` и `Shift+Insert` (или `Ctrl+C` и `Ctrl+V`), помеченные, чтобы свой перехватчик их пропускал |
| `Foreground` | Окно с фокусом, терминалы, удалённые столы, уровень прав окна |
| `InputSources` | Список раскладок, имена, таблицы через `ToUnicodeEx`, текущая раскладка, переключение |
| `SettingsStore` | Настройки в `HKCU\Software\Klats` |
| `LoginItem` | Автозапуск через ключ `Run` и состояние из Диспетчера задач |
| `UpdateChecker` | Раз при запуске читает ленту релизов и предлагает скачать новую версию |
| `Tray`, `SettingsWindow`, `OnboardingWindow`, `AboutWindow`, `HotkeyRecorder` | Значок, меню и окна |
| `Strings` | Русский и английский; ключи — русские строки, как на маке |
| `Log` | Журнал в `%LOCALAPPDATA%\Klats\klats.log`, до 1 МБ, потом `klats.log.old`. Текста в нём нет никогда |

### Потоки

- **Поток интерфейса.** Скрытое окно-владелец значка (обычное окно верхнего уровня: только такие получают `TaskbarCreated` и `WM_SETTINGCHANGE`), меню, окна, `TaskDialog`.
- **Поток перехватчика.** Ставит `WH_KEYBOARD_LL`, крутит цикл сообщений и больше ничего не делает. Колбэк только ведёт детектор и решает, проглотить ли клавишу. Действие уходит в поток конвейера сообщением. Ни журнала, ни диска, ни ожиданий внутри колбэка.
- **Поток конвейера.** Невидимое окно-владелец буфера обмена и конвейер как автомат на таймерах. Этот поток никогда не спит: пока Клац владеет буфером, чужой `EmptyClipboard` синхронно ждёт ответа владельца, и спящий поток подвесил бы копирование во всей системе. Поэтому же тестовое поле первого запуска (оно на потоке интерфейса) отвечает на `Ctrl+Insert`.
- **Проверка обновлений** — короткий поток с WinHTTP, результат уходит в поток интерфейса.

### Сочетания

- Модификаторы Клац ведёт сам по событиям перехватчика: левая и правая клавиша — один модификатор. Нейтральные коды Shift, Ctrl и Alt переводятся в левый и правый по скан-коду.
- Фальшивые события со скан-кодом `0x21D`, `0x22A` и `0x236` (бит `0x200`) не считаются ничем: это Ctrl, который Windows подмешивает к AltGr, и Shift для цифровой клавиатуры.
- Свои нажатия помечены `dwExtraInfo = 0x4B4C4154` («KLAT», младший бит ноль, как требует PowerToys) и проходят мимо детектора. Чужие синтетические модификаторы считаются модификаторами (ремапперы PowerToys и AutoHotkey), чужие синтетические клавиши — «другим вводом».
- Автоповтор зажатого модификатора в детектор не идёт: туда попадает только смена набора модификаторов. Время удержания Клац меряет своими часами, а не полем `time` события: у событий AltGr оно бывает нулевым.
- Мышиный перехватчик ставится, когда нажат первый модификатор любого из сочетаний, и снимается, когда отпущены все. Нажатия кнопок и прокрутка — «другой ввод», движения не в счёт. В момент срабатывания дополнительно проверяется, не зажата ли кнопка мыши.
- Сочетание из одних модификаторов срабатывает на том отпускании, после которого набор перестаёт совпадать. До того как пропустить это отпускание дальше, Клац посылает `vkE8↓↑` с маркером, и ни «Пуск», ни меню программы не открываются.
- Обычное сочетание (`Win+Alt+Z`): нажатие `Z` проглатывается вместе с автоповтором и отпусканием `Z`, даже если модификаторы отпустили раньше. Маска `vkE8` идёт сразу при проглатывании.
- Перехватчик ставится заново после разблокировки, выхода из сна и включения экрана, а также если `UnhookWindowsHookEx` ответил `ERROR_INVALID_HOOK_HANDLE` (значит, Windows его уже сняла). Каждая переустановка пишется в журнал. Детектор сбрасывается при блокировке и смене рабочего стола.
- Только 64-битная сборка: по данным сообщества Windows молча снимает перехватчики 32-битных процессов после серии задержек.

Правила для `Win+Alt` те же, что для `⌥⌘` на маке: к сочетанию пришли нажатием, пока оно было зажато, не было ни клавиш, ни кликов, ни прокрутки, не добавлялись модификаторы, удержание короче секунды, кнопки мыши не зажаты. После срабатывания нужно отпустить всё.

### Одно нажатие по шагам

1. Сочетание поймано. Поток конвейера запоминает окно с фокусом (`GetGUIThreadInfo(0)`) и его процесс.
2. Пропуск: класс окна или процесс из списка терминалов, удалённых столов и виртуальных машин (`ConsoleWindowClass`, `CASCADIA_HOSTING_WINDOW_CLASS`, `IHWindowClass` встроенного RDP, `mintty.exe`, `mstsc.exe`, `vmware.exe` и другие), полноэкранное приложение Direct3D, окно зависло (`IsHungAppWindow`), уровень прав процесса окна выше, чем у Клаца, или его не удалось узнать. Выходим, ничего не трогая, в журнал — причина и имя процесса.
3. Ждём до 0,6 с, пока `GetAsyncKeyState` покажет отпущенными Shift, Ctrl, Alt и Win. Не отпустили — выходим.
4. Снимок буфера (см. ниже). Владелец буфера не отвечает на пинг за 150 мс или снимок не уложился в бюджет — выходим, буфер не тронут.
5. Окно с фокусом то же? Нет — выходим. `Ctrl+Insert` одним вызовом `SendInput`. Ждём до 0,5 с `WM_CLIPBOARDUPDATE` или изменения `GetClipboardSequenceNumber`. Нет изменения — выходим, буфер не тронут.
6. В одном открытии буфера: читаем `CF_UNICODETEXT` (до первого нуля). Нет текста или это копия строки из редактора (форматы `MSDEVLineSelect`, `VisualStudioEditorOperationsLineCutCopyClipboardTag` или `vscode-editor-data` с `isFromEmptySelection`) — возвращаем снимок, выходим.
7. Преобразование. Таблицы раскладок строятся тут же, кэша нет. Ничья — исходной считается раскладка потока окна с фокусом.
8. Результат не отличается — возвращаем снимок, выходим.
9. Окно с фокусом то же и не попало в пропуск (проверка ещё раз)? Нет — возвращаем снимок, выходим. Иначе в том же открытии буфера: `EmptyClipboard`, `CF_UNICODETEXT`, `CF_LOCALE` языка результата и пометки `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory = 0`, `CanUploadToCloudClipboard = 0`, `Clipboard Viewer Ignore`. Запоминаем номер буфера после `CloseClipboard`. Затем `Shift+Insert`.
10. Переключение раскладки, если включено (см. ниже).
11. Ждём `max(300 мс, 200 мс + 3 × время ответа на копирование)`, не больше 2 с. Номер буфера не изменился — возвращаем снимок. Буферы снимка затираются (`SecureZeroMemory`): там может быть скопированный пароль.

Выход из Клаца, завершение сеанса и сон во время шагов 9–11 сначала возвращают снимок, потом всё остальное. Окно-владелец буфера `WM_RENDERFORMAT` и `WM_RENDERALLFORMATS` отдаёт `DefWindowProc`: отложенной выдачи у Клаца нет.

Копировать и вставлять через `Ctrl+C` и `Ctrl+V` Клац начинает сам, если `SystemParametersInfo(SPI_GETSCREENREADER)` включён (NVDA и JAWS держат `Insert`), или если в реестре `CopyKeys = "ctrl"` — для тех, у кого `Insert` отключён переназначением.

В VS Code и его родне (`Code.exe`, `Cursor.exe`, `VSCodium.exe`, `Windsurf.exe`) многострочный результат вставляется, только если копия пришла из редактора (есть формат `Chromium Web Custom MIME Data Format` с `vscode-editor-data`): встроенный терминал этой пометки не ставит, а вставка туда исполнила бы строки.

### Буфер обмена

- **Снимок.** Все форматы в порядке `EnumClipboardFormats`. Данные `HGLOBAL` копируются байтами. `CF_ENHMETAFILE` и `CF_METAFILEPICT` — через `GetEnhMetaFileBits` и `GetMetaFileBitsEx`. Не читаются: `CF_BITMAP` и `CF_PALETTE` (Windows соберёт их из DIB), второй из пары `CF_DIB`/`CF_DIBV5`, `CF_OWNERDISPLAY`, частные форматы `0x200–0x2FF`, `FileContents` и OLE-ссылки (`Link Source`, `ObjectLink`, `OwnerLink`, `Native`, `Embed Source`). Форматы, где важно само присутствие (`MSDEVLineSelect`, `MSDEVColumnSelect`, `VisualStudioEditorOperationsLineCutCopyClipboardTag`, `WebKit Smart Paste Format`), не читаются и возвращаются однобайтовым блоком.
- **Бюджет.** До чтения — пинг владельца буфера `SendMessageTimeout(WM_NULL, SMTO_ABORTIFHUNG, 150 мс)`. После каждого формата — проверка: до 64 МБ на формат и до 300 мс на весь снимок. Превышение — выход до `Ctrl+Insert`, в журнал «буфер слишком большой».
- **Возврат.** Все сохранённые форматы в исходном порядке, включая `CF_TEXT`, `CF_OEMTEXT` и `CF_LOCALE` байт в байт. Без пометок: если пометки были в снимке (пароль из менеджера паролей), они вернутся вместе с ним.
- **Открытие буфера** — с повтором до 0,5 с: первые 20 мс часто, потом раз в 10 мс, ожидание через таймер. Неудача — в журнал, кто держит буфер (`GetOpenClipboardWindow`).

### Раскладки

- **Список.** `EnumEnabledLayoutOrTip` из `input.dll`: включённые пользователем раскладки с идентификаторами `LANGID:KLID`, как их пишет сама Windows. Методы ввода (TIP) и KLID, начинающиеся с `E`, отбрасываются. KLID переводится в HKL (`0000xxxx` → язык и раскладка; иначе `Layout Id` из реестра → `0xF000 | id`) и сверяется с `GetKeyboardLayoutList`. Пара «авто» — ровно две раскладки с разными таблицами, иначе выбор в параметрах. HKL `0` и незагруженные раскладки в таблицы не попадают никогда.
- **Имена.** `RegLoadMUIStringW` из `Layout Display Name` («Русская», «США»), запасной вариант — `Layout Text`.
- **Таблицы.** Скан-коды основного блока: `0x02–0x0D`, `0x10–0x1B`, `0x1E–0x29`, `0x2B–0x35`, `0x56`, `0x73`, `0x7D`; без Shift и с Shift. VK раскладки — `MapVirtualKeyExW(sc, MAPVK_VSC_TO_VK_EX)`, символ — `ToUnicodeEx` с флагом `4` (не трогать общее состояние клавиатуры). Берётся результат ровно из одной графемы, не пробел и не управляющий символ. Мёртвые клавиши пока пропускаются, как на маке; решение по ним — после проверки с US-International, немецкой и «Русской — мнемонической».
- **Текущая раскладка** — раскладка потока окна с фокусом. Для консоли поток берётся у IME-окна (`ImmGetDefaultIMEWnd`), иначе `GetKeyboardLayout` вернёт ноль.
- **Переключение.** `PostMessage(WM_INPUTLANGCHANGEREQUEST, 0, HKL)` окну с фокусом, затем до 150 мс ждём, что раскладка его потока сменилась; нет — то же окну верхнего уровня; нет — в журнал «раскладка не переключилась». Полный HKL, а не язык: у «США» и «США — Дворак» язык один.

### Обновления

Раз при запуске `UpdateChecker` читает `https://github.com/belokoz/klats/releases.atom` через WinHTTP с системным прокси и `User-Agent: Klats/<версия> (Windows)`. Это единственный сетевой запрос приложения: без текста, настроек и идентификаторов. Лента не расходует лимит API GitHub.

- В ленте берутся записи с `id` вида `tag:github.com,2008:Repository/1375942669/windows-vX.Y.Z`: номер репозитория должен совпасть, после `windows-v` — только цифры и точки. Пробные сборки с суффиксом в теге не предлагаются.
- Из записи берётся ссылка `https://github.com/<владелец>/<репозиторий>/releases/tag/windows-vX.Y.Z`, из неё — ссылка на установщик `…/releases/download/windows-vX.Y.Z/Klats-X.Y.Z-windows-x64.exe`. Открывается только `https://github.com`.
- Самая новая версия больше своей — окно «Вышел Клац X.Y.Z». Оно появляется, когда клавиатура 3 секунды в покое (`GetLastInputInfo`): так Enter из чужого набора не нажмёт «Скачать».
- Проверки нет при первом запуске, при выключенной настройке и при `--debug-show`. При входе в систему сеть может ещё не подняться: запрос ждёт её до двух минут. Нет сети или ответа — пишем в журнал и молчим.
- `--debug-pretend-version 0.0.1` проверяет так, будто запущена старая версия.

Правила выпуска — в [CONCEPT.md](CONCEPT.md#релизы-в-общем-репозитории); их проверяет `windows/scripts/make-release.ps1`.

### Настройки и автозапуск

Значения в `HKCU\Software\Klats`:

| Значение | Тип | Смысл |
|---|---|---|
| `LayoutHotkey`, `CaseHotkey` | DWORD | Биты 0–7 — VK (0 для сочетания из модификаторов), биты 8–11 — Shift, Ctrl, Alt, Win. `0` — сочетание убрано; значения нет — по умолчанию |
| `SwitchLayoutAfterConversion` | DWORD | 1 по умолчанию |
| `CaseMode` | SZ | `invert` или `lowercase` |
| `LayoutPair` | MULTI_SZ | Две строки `LANGID:KLID`; пусто — «авто» |
| `OnboardingCompleted`, `CheckForUpdates` | DWORD | |
| `CopyKeys` | SZ | `ctrl` — копировать через `Ctrl+C`; в интерфейсе не показывается |

Автозапуск: значение `Klats` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` с путём к exe и `--autostart`. Включён, если значение есть, а в `…\Explorer\StartupApproved\Run` значения `Klats` нет или его первый байт `00` либо `02`; иначе в параметрах написано «выключено в Диспетчере задач». Включение из Клаца пишет `Run` и удаляет отметку Диспетчера задач, выключение удаляет оба значения. При ручном запуске (без `--autostart`) путь в `Run` обновляется, если exe переехал.

Один экземпляр: мьютекс `Local\io.github.belokoz.klats`. Второй запуск находит окно первого по классу и просит его открыть параметры.

## Сборка и тесты

Нужны Visual Studio Build Tools 2022 (MSVC 14.44, Windows SDK, CMake и Ninja входят).

```powershell
cd windows
.\build.ps1            # чистая сборка build\release\Klats.exe и тесты ядра
```
