# Клац для Windows — дизайн

Принят 5 октября 2026. Продуктовые решения описаны в [CONCEPT.md](CONCEPT.md), мак-версия — в [../DESIGN.md](../DESIGN.md). Здесь только то, что на Windows устроено иначе.

## Окна

Номера совпадают с экранами мак-версии.

1. **Меню значка.** «Сменить раскладку выделенного» `Win+Alt`, «Сменить регистр выделенного» `Win+Alt+Z`, «Приостановить» (галочка), «Параметры…» (жирный, по умолчанию), «О программе», «Выход». Сочетания стоят справа, через табуляцию. Открывается сразу по левому и правому щелчку и с клавиатуры; у двойного щелчка своего действия нет. «Открыть журнал» появляется, если открыть меню мышью с зажатым Shift. Если включено больше двух раскладок, а пара не выбрана, над действиями стоит «Выберите пару раскладок…»: он открывает параметры. Меню, закрытое Esc или «Приостановить», возвращает фокус в область уведомлений (`NIM_SETFOCUS`).
2. **Параметры.** Одно окно без вкладок, четыре группы: сочетания клавиш (два поля записи), раскладка (пара раскладок, «Переключать раскладку после конвертации»), регистр («Инвертировать» или «Все строчные», с примером), общие («Запускать при входе в Windows», «Проверять обновления при запуске»). При двух раскладках пара — строка «США ⇄ Русская», при трёх и больше — два списка; пока пара не выбрана, в них ничего не выбрано. Внизу версия, лицензия, ссылка на репозиторий и «Диктуй: голос в текст». Изменения применяются сразу, кнопок «ОК» и «Отмена» нет.
3–4. **Первый запуск.** Одно окно, шагов с разрешением нет. «Попробуйте»: поле с выделенным «ghbdtn vbh» и подсказка про `Win+Alt`. «Где живёт Клац»: как вытащить значок из-за стрелки ^ на панель задач. Галочка «Запускать Клац при входе в Windows» (стоит) и «Готово». Строка: в окнах программ, запущенных от имени администратора, Клац не работает.
5. **Поле записи сочетания.** Те же состояния, что на маке: обычное, запись, запись с зажатыми клавишами, занято системой, занято другим действием, не задано. Клавиши подписаны текстом: `Win`, `Ctrl`, `Alt`, `Shift` в этом порядке, буквы и `Пробел`.
6. **Меню, когда впереди окно администратора.** Первой строкой «Окно администратора: здесь Клац не работает». Если перехватчик не встал — «Клац не может следить за клавиатурой».
7. **Меню на паузе.** Действия убраны, у «Приостановить» галочка, значок приглушён.
8–9. **Тёмная и светлая тема.** Значок и меню следуют теме панели задач, окна — теме приложений (если тёмные окна пройдут проверку к 0.1).
10. **Значок.** Клавиша с K и Л, как на маке, в exe и ярлыке. В области уведомлений — контур клавиши с K: белый на тёмной панели задач, тёмный на светлой, в контрастной теме — цветом текста темы. Размер — малый значок при DPI панели задач (`GetDpiForWindow(Shell_TrayWnd)`): 16, 20 или 24 пикселя.
11. **Вышел Клац …** Окно с кнопками «Скачать» и «Не сейчас»; Esc — «Не сейчас».

Тексты интерфейса на «вы». Контролы стандартные Win32, шрифт — системный шрифт сообщений (Segoe UI). Ссылки — синий текст без подчёркивания: SysLink и `TaskDialog` подчёркивают всегда, поэтому ссылки — SysLink с `LWS_USECUSTOMTEXT`, и на `NM_CUSTOMTEXT` окно подставляет им свой шрифт и цвет `COLOR_HOTLIGHT`.

## Устройство

Код в папке `windows/`. Два слоя, как на маке.

**core** (`windows/src/core`) — чистая логика без вызовов Windows, покрыта тестами. Юникод даёт ICU из Windows (`icu.dll`).

| Тип | Что делает |
|---|---|
| `Modifiers`, `ChordDetector` | Четыре модификатора (Shift, Ctrl, Alt, Win) и автомат сочетания из одних модификаторов, перенос с мака |
| `Hotkey` | Сочетание: клавиша (VK) плюс модификаторы, хранится в реестре одним числом |
| `KeyStroke`, `LayoutTable` | Раскладка как две таблицы; клавиша — это скан-код плюс Shift |
| `choosePair` | Какие две раскладки конвертировать: выбранная пара или «авто» |
| `LayoutConverter` | Направление по тексту и перепечатка в другой раскладке |
| `CaseConverter` | Инвертировать или всё строчными, по правилам Swift |
| `Unicode` | Графемы, NFC и регистр через ICU |
| `AppVersion`, `readReleaseFeed` | Номер версии и Windows-релизы страницы ленты `releases.atom` |

**app** (`windows/src/app`) — всё, что трогает систему.

| Тип | Что делает |
|---|---|
| `HookThread` | Поток с `WH_KEYBOARD_LL` и, на время сочетания, `WH_MOUSE_LL`: детектор, маска `vkE8`, запись сочетания для поля настроек |
| `Pipeline` | Конвейер одного нажатия на своём потоке |
| `ClipboardSnapshot` | Снимок буфера обмена и его возврат |
| `SyntheticKeys` | `Ctrl+Insert` и `Shift+Insert` (или `Ctrl+C` и `Ctrl+V`), помеченные, чтобы свой перехватчик их пропускал |
| `Foreground` | Окно с фокусом, терминалы, удалённые столы, уровень прав окна |
| `InputSources` | Список раскладок, имена, таблицы через `ToUnicodeEx`, текущая раскладка, переключение |
| `SettingsStore` | Настройки в `HKCU\Software\Klats` |
| `LoginItem` | Автозапуск через ключ `Run` и состояние из Диспетчера задач |
| `UpdateChecker` | Раз при запуске читает ленту релизов и предлагает скачать новую версию |
| `TrayIcon`, `SettingsWindow`, `OnboardingWindow`, `AboutWindow`, `HotkeyRecorder` | Значок, меню и окна; «Вышел Клац» — `TaskDialog` |
| `Strings` | Русский и английский; ключи — русские строки, как на маке |
| `Log` | Журнал в `%LOCALAPPDATA%\Klats\klats.log`, до 1 МБ, потом `klats.log.old`. Текста в нём нет никогда |

### Потоки

- **Поток интерфейса.** Скрытое окно-владелец значка (обычное окно верхнего уровня: только такие получают `TaskbarCreated` и `WM_SETTINGCHANGE`), меню, окна, `TaskDialog`. Пишет в журнал и то, что сообщает поток перехватчика.
- **Поток перехватчика.** Ставит `WH_KEYBOARD_LL` и `SetWinEventHook(EVENT_SYSTEM_DESKTOPSWITCH)`, крутит цикл сообщений и больше ничего не делает. Колбэк только ведёт детектор и решает, проглотить ли клавишу. Действие уходит в поток конвейера сообщением, переустановка и ошибки перехватчика — в поток интерфейса. Ни журнала, ни диска, ни ожиданий на этом потоке.
- **Поток конвейера.** Невидимое окно-владелец буфера обмена и конвейер. Этот поток никогда не спит: пока Клац владеет буфером, чужой `EmptyClipboard` синхронно ждёт ответа владельца, и спящий поток подвесил бы копирование во всей системе. Поэтому же тестовое поле первого запуска (оно на потоке интерфейса) отвечает на `Ctrl+Insert`.
- **Проверка обновлений** — короткий поток с WinHTTP, результат уходит в поток интерфейса.

### Сочетания

- Модификаторы Клац ведёт сам по событиям перехватчика: левая и правая клавиша — один модификатор. Нейтральные коды Shift, Ctrl и Alt переводятся в левый и правый по скан-коду.
- Фальшивые события со скан-кодом `0x21D`, `0x22A` и `0x236` (бит `0x200`) не считаются ничем: это Ctrl, который Windows подмешивает к AltGr, и Shift для цифровой клавиатуры.
- Свои нажатия помечены `dwExtraInfo = 0x4B4C4154` («KLAT», младший бит ноль, как требует PowerToys) и проходят мимо детектора. Чужие синтетические модификаторы считаются модификаторами (ремапперы PowerToys и AutoHotkey), чужие синтетические клавиши — «другим вводом».
- Автоповтор зажатого модификатора в детектор не идёт: туда попадает только смена набора модификаторов. Время удержания Клац меряет своими часами, а не полем `time` события: у событий AltGr оно бывает нулевым.
- Мышиный перехватчик ставится, когда нажат первый модификатор любого из сочетаний, и снимается, когда отпущены все. Нажатия кнопок и прокрутка — «другой ввод», движения не в счёт. В момент срабатывания дополнительно проверяется, не зажата ли кнопка мыши.
- Сочетание из одних модификаторов срабатывает на том отпускании, после которого набор перестаёт совпадать. До того как пропустить это отпускание дальше, Клац посылает `vkE8↓↑` с маркером, и ни «Пуск», ни меню программы не открываются.
- Обычное сочетание (`Win+Alt+Z`): нажатие `Z` проглатывается вместе с автоповтором и отпусканием `Z`, даже если модификаторы отпустили раньше. Маска `vkE8` идёт сразу при проглатывании.
- Отпускания, которых перехватчик не видит (Ctrl+Alt+Del, окно UAC, окно администратора), не должны оставлять модификатор «зажатым». При смене рабочего стола и блокировке состояние сбрасывается целиком. При каждом нажатии модификатор, который Клац считает зажатым, а `GetAsyncKeyState` — отпущенным, снимается, и сочетания начинаются заново; внутри колбэка состояние верно для всех клавиш, кроме текущей, а для текущей «отпущена» значит, что прошлое отпускание потерялось. `GetAsyncKeyState` только снимает, никогда не ставит: при запрете он отвечает «отпущена». Проглоченные клавиши Windows не видела, для них считается время: нажатие после 2,5 с тишины — новое, а не автоповтор.
- Запись сочетания: пока окно параметров впереди и поле записывает, все клавиши уходят в него и до Windows не доходят, сочетания молчат. Клавиша, нажатая до начала записи, отпускается как обычно, проглоченная — проглатывается и после записи.
- Перехватчик ставится заново после разблокировки, выхода из сна и включения экрана, а также если `UnhookWindowsHookEx` ответил `ERROR_INVALID_HOOK_HANDLE` (значит, Windows его уже сняла). Каждая переустановка пишется в журнал.
- Только 64-битная сборка: по данным сообщества Windows молча снимает перехватчики 32-битных процессов после серии задержек.

Правила для `Win+Alt` те же, что для `⌥⌘` на маке: к сочетанию пришли нажатием, пока оно было зажато, не было ни клавиш, ни кликов, ни прокрутки, не добавлялись модификаторы, удержание короче секунды, кнопки мыши не зажаты. После срабатывания нужно отпустить всё.

### Одно нажатие по шагам

1. Сочетание поймано. Поток конвейера запоминает окно с фокусом (`GetGUIThreadInfo(0)`) и его процесс.
2. Пропуск: класс окна или процесс из списка терминалов, удалённых столов и виртуальных машин (`ConsoleWindowClass`, `CASCADIA_HOSTING_WINDOW_CLASS`, `IHWindowClass` встроенного RDP, `mintty.exe`, `mstsc.exe`, `vmware.exe` и другие), полноэкранное приложение Direct3D, окно зависло (`IsHungAppWindow`), уровень прав процесса окна выше, чем у Клаца, или его не удалось узнать. Выходим, ничего не трогая, в журнал — причина и имя процесса.
3. Для раскладки — пара раскладок и их таблицы (см. «Раскладки»). Пары нет — выходим, буфер не тронут.
4. Ждём до 0,6 с, пока `GetAsyncKeyState` покажет отпущенными Shift, Ctrl, Alt и Win. Не отпустили — выходим.
5. Снимок буфера (см. ниже). Владелец буфера не отвечает на пинг за 150 мс или снимок не уложился в бюджет — выходим, буфер не тронут.
6. Окно с фокусом то же? Нет — выходим. `Ctrl+Insert` одним вызовом `SendInput`. Ждём до 0,5 с изменения `GetClipboardSequenceNumber`. Нет изменения — выходим, но снимок ещё 5 с ждёт запоздалой копии (`AddClipboardFormatListener`): занятая программа может скопировать позже и затереть буфер. Первую смену буфера за это время Клац откатывает к снимку, если её сделала та же программа и пользователь ничего не напечатал; копию мышью от запоздалой не отличить.
7. В одном открытии буфера: номер буфера и текст. Текст — `CF_UNICODETEXT` до первого нуля; если программа положила только `CF_TEXT`, а `CF_LOCALE` совпадает с языком раскладки окна, — `CF_TEXT` в кодировке системы (иначе с английской раскладкой русская ANSI-программа отдаёт «ïÐÈÂÅÒ»). Возвращаем снимок и выходим, если текста нет, он длиннее 512 тысяч символов (около 0,1 с работы) или это копия строки из редактора: `MSDEVLineSelect`, `VisualStudioEditorOperationsLineCutCopyClipboardTag`, `vscode-editor-data` с `isFromEmptySelection`, формат JetBrains `JAVA_DATAFLAVOR:…CopyPasteOptionsTransferableData` с `…FromEmptySelection = true`, в Sublime Text — ровно одна строка с переводом строки в конце. Блочное выделение (`MSDEVColumnSelect` или `Borland IDE Block Type = 2`) запоминается.
8. Преобразование. Ничья — исходной считается раскладка потока окна с фокусом.
9. Результат не отличается или в нём другое число переводов строк — возвращаем снимок, выходим.
10. Окно с фокусом то же и не попало в пропуск (проверка ещё раз)? Нет — возвращаем снимок, выходим. Иначе в открытии буфера, если номер буфера тот же, что при чтении: `EmptyClipboard`, `CF_UNICODETEXT`, `CF_LOCALE`, для блочного выделения те же две пометки, и пометки `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory = 0`, `CanUploadToCloudClipboard = 0`, `Clipboard Viewer Ignore`. Номер другой — выходим, ничего не трогая: в буфере уже что-то новое от пользователя. `CF_LOCALE` — системный, если текст укладывается в кодировку системы, иначе язык раскладки результата: ANSI-программы читают `CF_TEXT` в кодировке системы, а Windows делает его в кодировке `CF_LOCALE`. Запоминаем номер буфера после `CloseClipboard`.
11. Ждём, пока буфер 25 мс никто не держит (не дольше 0,2 с): поле Блокнота открывает буфер один раз и сдаётся, если в этот миг его читает кто-то другой. Последняя проверка без пауз перед клавишами: Клац не выходит, фокус там же и не в пропуске; иначе возвращаем снимок. `Shift+Insert`.
12. Переключение раскладки, если включено (см. ниже).
13. Ждём `max(300 мс, 200 мс + 3 × время ответа на копирование)`, не больше 2 с. Возвращаем снимок, если номер буфера тот же; буфер занят — ждём до 2 с, пока номер не изменится. Буферы снимка затираются (`SecureZeroMemory`): там может быть скопированный пароль.

Каждый возврат снимка сверяет номер буфера внутри открытия, где его никто не изменит: скопированное пользователем за время конвертации остаётся в буфере.

На время одной конвертации Клац включает таймер Windows с шагом 1 мс (`timeBeginPeriod`): с обычным шагом 15,6 мс каждое ожидание затягивается, а короткие захваты буфера другими программами не видны. Время меряется по `QueryPerformanceCounter`, а не `GetTickCount64`: тот шагает по 15,6 мс и при включённом таймере.

Выход из Клаца и завершение сеанса во время шагов 10–13 сначала возвращают снимок, потом всё остальное; если `Shift+Insert` уже ушёл, вставке дают 0,1 с. Окно-владелец буфера `WM_RENDERFORMAT` и `WM_RENDERALLFORMATS` отдаёт `DefWindowProc`: отложенной выдачи у Клаца нет.

Копировать и вставлять через `Ctrl+C` и `Ctrl+V` Клац начинает сам, если `SystemParametersInfo(SPI_GETSCREENREADER)` включён (NVDA и JAWS держат `Insert`), или если в реестре `CopyKeys = "ctrl"` — для тех, у кого `Insert` отключён переназначением.

В VS Code и его родне (`Code.exe`, `Cursor.exe`, `VSCodium.exe`, `Windsurf.exe`) многострочный результат вставляется, только если копия пришла из редактора (есть формат `Chromium Web Custom MIME Data Format` с `vscode-editor-data`): встроенный терминал этой пометки не ставит, а вставка туда исполнила бы строки.

### Буфер обмена

- **Снимок.** Все форматы в порядке `EnumClipboardFormats`. Данные `HGLOBAL` копируются байтами. `CF_ENHMETAFILE` и `CF_METAFILEPICT` — через `GetEnhMetaFileBits` и `GetMetaFileBitsEx`. Не читаются: `CF_BITMAP` и `CF_PALETTE` (Windows соберёт их из DIB), второй из пары `CF_DIB`/`CF_DIBV5`, `CF_OWNERDISPLAY`, частные форматы `0x200–0x2FF`, `FileContents` и OLE-ссылки (`Link Source`, `ObjectLink`, `OwnerLink`, `Native`, `Embed Source`). Форматы, где важно само присутствие (`MSDEVLineSelect`, `MSDEVColumnSelect`, `VisualStudioEditorOperationsLineCutCopyClipboardTag`, `WebKit Smart Paste Format`), не читаются и возвращаются однобайтовым блоком.
- **Бюджет.** До чтения — пинг владельца буфера `SendMessageTimeout(WM_NULL, SMTO_ABORTIFHUNG, 150 мс)`. После каждого формата — проверка: до 64 МБ на формат и до 300 мс на весь снимок. Превышение — выход до `Ctrl+Insert`, в журнал «буфер слишком большой».
- **Возврат.** Все сохранённые форматы в исходном порядке, включая `CF_TEXT`, `CF_OEMTEXT` и `CF_LOCALE` байт в байт. Без пометок: если пометки были в снимке (пароль из менеджера паролей), они вернутся вместе с ним.
- **Открытие буфера** — с повтором до 0,5 с: первые 20 мс часто, потом раз в 10 мс. Неудача — в журнал, кто держит буфер (`GetOpenClipboardWindow`).

### Раскладки

- **Список.** `EnumEnabledLayoutOrTip` из `input.dll`: включённые пользователем раскладки с идентификаторами `LANGID:KLID`, как их пишет сама Windows, по порядку языков, а не пользователя. Методы ввода (TIP) и KLID, начинающиеся с `E`, отбрасываются. KLID переводится в HKL (`0000xxxx` → язык и раскладка; иначе `Layout Id` из реестра → `0xF000 | id`) и сверяется с `GetKeyboardLayoutList`. HKL `0` и незагруженные раскладки в таблицы не попадают никогда.
- **Пара.** Выбранная в параметрах, если обе её раскладки включены. Иначе «авто»: раскладки с пустыми таблицами не в счёт, одна клавиатура под двумя языками — одна раскладка; осталось ровно две — они, больше — пару выбирает пользователь, первые две из списка были бы гаданием.
- **Имена.** `RegLoadMUIStringW` из `Layout Display Name` («Русская», «США»), запасной вариант — `Layout Text`.
- **Таблицы.** Строятся заново на каждое нажатие, кэша нет. Скан-коды основного блока: `0x02–0x0D`, `0x10–0x1B`, `0x1E–0x29`, `0x2B–0x35`, `0x56`, `0x73`, `0x7D`; без Shift и с Shift. VK раскладки — `MapVirtualKeyExW(sc, MAPVK_VSC_TO_VK_EX)`, символ — `ToUnicodeEx` с флагом `4` (не трогать общее состояние клавиатуры). Берётся результат ровно из одной графемы, не пробел и не управляющий символ. Графемы длиннее 64 знаков UTF-16 в таблицах не ищутся: ни одна клавиша их не печатает, а нормализация огромного кластера диакритик квадратична. Мёртвые клавиши пока пропускаются, как на маке; решение по ним — после проверки с US-International, немецкой и «Русской — мнемонической».
- **Текущая раскладка** — раскладка потока окна с фокусом. Для консоли поток берётся у IME-окна (`ImmGetDefaultIMEWnd`), иначе `GetKeyboardLayout` вернёт ноль.
- **Переключение.** `PostMessage(WM_INPUTLANGCHANGEREQUEST, 0, HKL)` окну с фокусом, затем до 150 мс ждём, что раскладка его потока сменилась; нет — то же окну верхнего уровня; нет — в журнал «раскладка не переключилась». Полный HKL, а не язык: у «США» и «США — Дворак» язык один.

### Обновления

Раз при запуске `UpdateChecker` читает `https://github.com/belokoz/klats/releases.atom` через WinHTTP с системным прокси и `User-Agent: Klats/<версия> (Windows)`. Эти запросы к github.com — единственные сетевые запросы приложения: без текста, настроек и идентификаторов. Лента не расходует лимит API GitHub.

- В ленте берутся записи с `id` вида `tag:github.com,2008:Repository/1375942669/windows-vX.Y.Z`: номер репозитория должен совпасть, после `windows-v` — только цифры и точки. Пробные сборки с суффиксом в теге не предлагаются.
- В ленте 10 последних записей общего репозитория, мак-релизы и пробные сборки тоже. Нет на странице Windows-релиза — следующая страница `releases.atom?after=<последний тег>`, не больше пяти; страница с повтором или неполная — конец.
- Из записи берётся ссылка `https://github.com/<владелец>/<репозиторий>/releases/tag/windows-vX.Y.Z`, из неё — ссылка на установщик `…/releases/download/windows-vX.Y.Z/Klats-X.Y.Z-windows-x64.exe`. Открывается только `https://github.com`.
- Тег без опубликованного релиза (удалённый или отправленный раньше файлов) в ленте выглядит как релиз. Поэтому перед окном — `HEAD` на ссылку установщика без перехода по редиректам: настоящий отвечает 302 на `*.githubusercontent.com`. Нет — следующая версия, не больше трёх.
- Версия новее своей — окно «Вышел Клац X.Y.Z». Оно появляется, когда клавиатура 3 секунды в покое (`GetLastInputInfo`): так Enter из чужого набора не нажмёт «Скачать».
- Проверки нет до конца первого запуска, при выключенной настройке и при `--debug-show`. При входе в систему сеть может ещё не подняться: первый запрос ждёт её до двух минут. Нет сети или ответа — пишем в журнал и молчим.
- `--debug-pretend-version 0.0.1` проверяет так, будто запущена старая версия.

Правила выпуска — в [CONCEPT.md](CONCEPT.md#релизы-в-общем-репозитории); их соблюдает workflow `.github/workflows/windows.yml` (см. «Сборка и тесты»).

### Настройки и автозапуск

Значения в `HKCU\Software\Klats`:

| Значение | Тип | Смысл |
|---|---|---|
| `LayoutHotkey`, `CaseHotkey` | DWORD | Биты 0–7 — VK (0 для сочетания из модификаторов), биты 8–11 — Shift, Ctrl, Alt, Win. `0` — сочетание убрано; значения нет — по умолчанию |
| `SwitchLayoutAfterConversion` | DWORD | 1 по умолчанию |
| `CaseMode` | SZ | `invert` или `lowercase` |
| `LayoutPair` | MULTI_SZ | Две строки `LANGID:KLID`; пусто — «авто» |
| `OnboardingCompleted`, `CheckForUpdates` | DWORD | |
| `CopyKeys` | SZ | `ctrl` — копировать через `Ctrl+C`; в интерфейсе не показывается |

Автозапуск: значение `Klats` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` с путём к exe и `--autostart`. Включён, если значение есть, а в `…\Explorer\StartupApproved\Run` значения `Klats` нет или его первый байт `00` либо `02`; иначе в параметрах написано «выключено в Диспетчере задач». Включение из Клаца пишет `Run` и удаляет отметку Диспетчера задач, выключение удаляет оба значения. При ручном запуске (без `--autostart`) путь в `Run` обновляется, если exe переехал.

### Установщик

Inno Setup 6, `windows/installer/klats.iss`. На одного пользователя, без прав администратора: `%LOCALAPPDATA%\Programs\Klats`, ярлык в «Пуске», удаление через «Параметры → Приложения». Язык — по языку интерфейса Windows: русский или английский.

- Запущенный Клац установщик и деинсталлятор закрывают сами, как пункт «Выход»: `WM_CLOSE` окну `KlatsTrayOwner`. Снимок буфера успевает вернуться, страницы «закройте программы» нет. Restart Manager — запасной путь; на его `WM_ENDSESSION` Клац выходит.
- После установки Клац запускается, и при тихой (`/VERYSILENT`) тоже: так обновление из окна «Вышел Клац» заканчивается работающей новой версией.
- Удаление убирает программу, ярлык, автозапуск (`Run` и `StartupApproved`) и журнал. Настройки в `HKCU\Software\Klats` остаются, как на маке.
- `AppId` в скрипте не менять никогда: по нему новая версия встаёт поверх старой.

### Один экземпляр

Мьютекс `Local\io.github.belokoz.klats`. Второй запуск находит окно первого по классу (ждёт его до 3 с) и просит его открыть параметры. Имя мьютекса может занять любая программа сеанса, поэтому без окна Клаца с тем же именем exe второй запуск пишет об этом в журнал и работает дальше.

## Сборка и тесты

Нужны Visual Studio Build Tools 2022 (MSVC 14.44, Windows SDK, CMake и Ninja входят), для установщика — Inno Setup 6 (`winget install JRSoftware.InnoSetup`).

```powershell
cd windows
.\build.ps1            # чистая сборка build\release\Klats.exe и тесты ядра
.\build.ps1 -Installer # и установщик build\release\Klats-X.Y.Z-windows-x64.exe
.\build.ps1 -Debug     # отладочная сборка
```

Номер версии — один, в `windows/CMakeLists.txt` (`project(Klats VERSION X.Y.Z)`): из него берут exe, установщик и тег.

На GitHub (`.github/workflows/windows.yml`, машина `windows-2022` с тем же набором инструментов, бесплатно для публичного репозитория): каждый пуш в `main`, который трогает `windows/`, собирает, гоняет тесты ядра и кладёт установщик в артефакты запуска. Выпуск — Actions → «Klats for Windows» → Run workflow: та же сборка, релиз `windows-vX.Y.Z` с `--latest=false`, проверка, что «последним» остался мак-релиз, и ссылки «Скачать для Windows» в `README.md` и `README.en.md` переходят на новую версию. Суффикс (`beta1`) делает пробный pre-release и README не трогает.

- C++20, `/W4 /permissive- /utf-8`, статическая CRT (`/MT`), `/guard:cf`, `/CETCOMPAT`, `/DEPENDENTLOADFLAG:0x800`. Manifest: Per-Monitor v2, Common Controls 6, `asInvoker`.
- `.rc` начинается с `#pragma code_page(65001)`, иначе кириллица в ресурсах молча портится. Исходники в UTF-8 без BOM. Шаблоны окон — в `res/dialogs.rc2`, без текстов: тексты ставит код из `strings.cpp`.
- Сборка всегда чистая: с одним русским языковым пакетом Build Tools Ninja теряет зависимости заголовков и ресурсов, а полная сборка идёт секунды.
- Тесты ядра — свой раннер в одном заголовке (`tests/test.h`), без зависимостей. Фикстуры раскладок сгенерированы `tools/dump_layouts` из раскладок Windows и не правятся руками.
- `klats_e2e [секунды]` — сквозная проверка запущенного Клаца на живом рабочем столе: Блокнот и WordPad, обе раскладки, регистр, пустое выделение, «Пуск» не открылся, буфер вернулся байт в байт. Забирает клавиатуру на полминуты.
- Флаги отладки: `--debug-show settings,onboarding,about,menu,update`, `--debug-pretend-version 0.0.1`, `--no-hook` (для отладчика: точка останова при живом перехватчике подвешивает ввод во всей системе).
